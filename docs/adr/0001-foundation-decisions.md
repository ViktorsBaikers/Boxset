# ADR 0001: Foundation decisions for Boxset

- **Status:** Accepted, 2026-10-14
- **Deciders:** project owner. Research was delegated to the planning session; see `docs/research/`.
- **Supersedes:** nothing. Later ADRs may supersede individual rows. Cite the row ID (for example `D-07`) when you do.

## Context

Boxset is a new, self-hosted application that replaces the two single-purpose reference applications, one for series and one for movies. It manages movies, series, and anime in one properly modelled product. The owner's constraints:
- no C#/.NET;
- no React;
- Tailwind CSS v4 is the only utility-class framework allowed (owner decision 2026-10-14, reversing the original "no Tailwind" constraint); no UnoCSS, Panda, or similar;
- actively maintained dependencies only;
- markedly faster than the two reference applications at large-library scale;
- friendly for newcomers while keeping veteran depth.

Product truth lives in `PRODUCT.md`. The visual system lives in `DESIGN.md`.

Eleven research dossiers (about 1,520 cited sources in total) and two source-code parity inventories informed every row below. They were verified live on 2026-10-14. These decisions are settled. Re-open one only by writing a superseding ADR that names the row and the new evidence.

| D-26 | Artwork cache | **Two tiers on local disk, AVIF only.** Boxset fetches TMDB's pre-sized files (posters `w500`, backdrops `w1280`, stills `w300`, profiles `w185`), never `original`, and encodes AVIF at the sizes the UI uses (posters 200 and 400 px, backdrops 780 and 1280 px) with the pure-Go WASM encoder (`gen2brain/avif`, `-tags nodynamic`). The source JPEG is discarded once encoded. **Pinned tier:** the current poster of every library title, about 32 KB each (about 0.5 GB at 15,000 titles), never evicted while the title is in the library. **LRU tier:** backdrops, season posters, episode stills, cast photos, logos, and search or discover results, fetched on first view through the same-origin `/img/` route and evicted by last access when the cache exceeds its cap (default 1 GB, set in Settings › System, which also shows usage and a Clear button). A removed title's poster drops to the LRU tier. Cache keys hash provider plus file path, which TMDB changes whenever the image changes, so responses are `Cache-Control: public, max-age=31536000, immutable` and repeat views cost no request. List payloads carry a ThumbHash (about 20 bytes) and dominant colour, so tiles paint before the image arrives. On a miss the source is served at once and AVIF encoding runs in a low-priority background queue. **Encoding runs out of process:** the WASM AVIF encoder keeps about 156 MB resident for the life of the process once used (measured in `prototypes/img-bench`), which would break the 60 MB idle budget. So the main process spawns `boxset artwork-worker` (the same binary) when the queue has work, with one encode goroutine per two cores; the worker exits after 30 s idle and its memory returns to the OS. Decoding, resizing and ThumbHash stay in-process (pure Go, no WASM). Last-access updates are batched, not written per request. Entries older than 180 days are refetched in a rolling background job (TMDB's six-month cache limit). The cache directory is rebuildable: it is excluded from backups and a deleted file is just a miss. No WebP copies: every browser in the floor decodes AVIF. | `prototypes/img-bench` (2026-10-14); owner request 2026-10-14 |
| D-27 | Speed beyond the budgets | Thirteen measures the budgets alone do not force: (1) **Warm reopen:** the service worker precaches the hashed app shell, and the TanStack Query cache is persisted to IndexedDB per user (cleared on sign-out), so a reopened tab paints the last Library at once and revalidates with ETags. (2) **No cold-load waterfall:** when Go serves the SPA entry for a route, it adds `<link rel="preload" as="fetch">` for that route's first API call, so data loads in parallel with the JS. (3) **Title rollup:** a `title_rollup` row per title (episode counts by state, a packed spine-run string, next airing, size), updated in the same transaction as episode, file and download changes, so Library lists and filters read one indexed table instead of joining 150k episodes. A property test recomputes it from scratch and must match. (4) **Streamed interactive search:** results appear per indexer as each one answers, with per-indexer status and timeout. The series and movie reference applications wait for every indexer (`Task.WhenAll`), so the slowest one sets the wait. (5) **Fast completion:** download clients are polled incrementally (qBittorrent `sync/maindata` with `rid`, SABnzbd/NZBGet history deltas) every 2 s while downloads are active and every 30 s when idle, plus an optional on-complete hook URL. Upstream checks once a minute. (6) **I/O per device:** rescans and probes run one worker per spinning disk (grouped by `dev`) and several per SSD. A device that cannot be classified (FUSE such as Unraid `/mnt/user` or mergerfs, network, Btrfs/ZFS anonymous major-0 devices, no `queue/rotational`) counts as spinning, with a per-root-folder override. "Low priority" is concrete: ffprobe children get `setpriority` nice 10 and the idle I/O class (`ioprio_set`), and in-process background pools stay within half the cores, so a Plex or Jellyfin transcode on the same box keeps its CPU. (7) **No re-probe on migration:** the importer copies the reference applications' `mediaInfo` from their APIs and only fills full stream details with ffprobe later, in the background. (8) **Use every core where it pays:** Go schedules goroutines on all cores (`GOMAXPROCS`, container-aware since Go 1.25, so a Docker `--cpus` limit is respected). CPU-bound passes fan out with `errgroup`: user-triggered passes (interactive-search decisions, manual import, a requested rebuild) use all cores (`SetLimit(GOMAXPROCS)`); background passes (RSS decisions, scheduled rollup rebuilds, AVIF encodes) stay within the background lane's half of the cores. HTTP requests already run in parallel. Not parallelised, on purpose: the single SQLite writer (writes are microseconds and batched) and network work bounded by indexer and provider rate limits, where more cores add nothing. (9) **Coalesced live updates:** the client buffers SSE events for about 250 ms, dedupes them, and issues one invalidation per affected query key; hidden tabs only mark queries stale (`refetchType: 'none'`) and refetch when visible; mutations `cancelQueries` in `onMutate` and skip invalidations for keys with a pending write, so a 1,000-title refresh causes one refetch, not 1,000, and optimistic toggles never flicker back. (10) **Bounded pages:** infinite queries set `maxPages` with two-way cursors, and only the first page of each list is persisted (`shouldDehydrateQuery`), so invalidation never refetches 200 pages and the persisted cache stays small. (11) **Back restores position:** a SvelteKit `snapshot` stores the virtua offset and anchor cursor and restores both from the query cache. (12) **Search-as-you-type:** `placeholderData: keepPreviousData`, the query's `AbortSignal` passed through `api.ts`, and a debounce of about 120 ms, so the grid never flashes empty and stale requests are cancelled. (13) **Rescans decoupled from refresh:** the series reference rescans every series after every 12-hour refresh by default (`RescanAfterRefresh=Always`, `ConfigService.cs:259`; `TaskManager.cs:109`), spinning up whole arrays twice a day. Boxset rescans on import, rename, or user request, plus a weekly sweep (configurable), and skips the file walk of any directory whose mtime is unchanged. Considered and rejected: client-side filtering of the whole library (duplicates the server's filter logic for a gain under 20 ms on a LAN; P-04 stays), h2c (no browser supports it), and Redis (D-05). | owner request 2026-10-14; the series reference's `ReleaseSearchService.Dispatch` and `TaskManager` (1-minute `RefreshMonitoredDownloads`) |

## Consequences

- Agents must use the Svelte MCP server and skills, enable runes mode, and pass lint bans on Svelte 4 idioms. Without these, Svelte 5 code regresses.
- The regexp2 engine is a single-maintainer dependency. Pin it and let the golden corpora guard upgrades.
- SQLite-only means users who want Postgres wait. The SQL stays portable, so pgx can be added later behind a second sqlc query set.
- The compatibility API costs an estimated 15–20% of backend effort. It is accepted, because it lets Seerr, Prowlarr, Bazarr, dashboards, and mobile apps work on day one.

## Revisit triggers

- A spike fails its stated budget: parser p99 > 1 ms per title in the ADR 0010 reference profile (Pi trigger replaced), list p95 > 20 ms at 150k episodes, or the runtime URL-base rewrite fails.
- Solid 2.0 or Vue Vapor goes stable *and* a measured Svelte bottleneck appears.
- TheTVDB refuses or revokes the project key.
- Under 6× CPU throttling on the dev server (standing in for a floor device; ADR 0010), a fast fling leaves AVIF tiles blank for more than 300 ms after the scroll stops: add a WebP variant for that device class or serve the 200 px variant only.
- AVIF encoding of a poster pair takes over 1 s in the ADR 0010 reference profile, or the WASM encoder's memory breaks the RSS budget (Pi trigger replaced): encode only the 400 px poster, or switch the tier to WebP (`gen2brain/webp`, about 5× faster).
- Bits UI ships no release for 6 months, or fails an accessibility gate it cannot fix: re-evaluate Ark UI behind the same `src/lib/ui/` wrappers.
- Library list p95 misses its budget after query and pragma tuning: add an in-memory read model for library lists, fed from committed events, with SQLite staying the source of truth. Do not switch databases.
- Users repeatedly need the database on shared or network storage, or a second app instance for failover: add Postgres as an opt-in backend (pgx behind a second sqlc query set). Speed alone is not a trigger.
